How to read this

Each row pairs a machine-checkable predicate over per-cell statistics, for example slow.p3s4.heldout < slow.p4s4.heldout, with the mechanism and control the model recorded before the data could answer. p and s name an (order, stages) cell, the leading word picks the cost model, and heldout in a predicate is that cell elite's error on the held-out set, which selects elites and so is not a clean test set.

Verdicts come from code, never from the model. Once every cell a predicate names holds min_samples records, the predicate is evaluated against those cells' running statistics. d is Cohen's d; below 0.2 the verdict is inconclusive whichever way the comparison went, so a weak effect cannot be claimed. A predicate that names an empty cell is inconclusive too, because absence of evidence never refutes. n is the smallest record count among the named cells, and c is the cycle the verdict landed on (c123+ means proposed at cycle 123 and still open).

×N means the model posed that predicate N times over the run. The row shows the newest verdict and lists the id of every posing; mixed beside the verdict means those posings did not all get the same one.

Embedded Runge, Kutta step control in fixed point collected 2026-09-25 18:54 CT, epoch 2, cycle 1650

Bogacki, Shampine 3(2) and Dormand, Prince 5(4) use shared stages to produce two solutions whose difference estimates local error. SciPy controls error using the lower-order estimate while advancing with the higher-order solution. SUNDIALS documents I and PI controllers that turn a tolerance-scaled error estimate into the next step size; PI control also uses the previous error. These methods address variable step sizes, so their usual accept/reject behavior must be accounted for when execution has a fixed cycle budget.

  • An embedded pair supplies a local error estimate from shared stage evaluations.
  • Bogacki, Shampine 3(2) and Dormand, Prince 5(4) are documented adaptive solver choices.
  • PI step control retains previous-error state.
  • Fixed-point quantization can create an error floor as steps shrink.
  • Cycle cost must include error estimation, controller arithmetic, and rejected steps.

Cortex-M0+ multiplication and constant arithmetic collected 2026-09-25 10:56 CT, epoch 2, cycle 1575

Arm documents two Cortex-M0+ multiplier implementations: MULS takes either 1 cycle or 32 cycles and returns only the low 32 bits of a 32-by-32-bit product. In Arm’s zero-wait-state timing table, additions, subtractions, and shifts each take 1 cycle. The selected multiplier and memory timing therefore matter when estimating a fixed cycle budget.

  • Cortex-M0+ MULS has implementation-dependent latency: 1 or 32 cycles.
  • MULS discards the upper 32 product bits.
  • Shifts consume instruction cycles on Cortex-M0+.
  • CSD minimizes signed-digit count, but a factored arithmetic graph can use fewer additions.
  • Cycle estimates should include the Q15 rounding step and any arithmetic needed to retain the required product bits.

Low-order Runge, Kutta tableau optimization collected 2026-09-25 09:17 CT, epoch 2, cycle 1525

Order conditions constrain a Runge, Kutta tableau but can leave free coefficients. For two-stage, second-order explicit methods, the second stage can be placed at a free node α; α = 1/2 gives midpoint, α = 1 gives Heun, and α = 2/3 gives Ralston’s method, which minimizes a specified leading local-error measure. The objective matters: minimizing error coefficients and enlarging the stability region are distinct searches. RK-Opt implements searches over fixed stage count and order with either leading truncation error or strong-stability objectives, and permits stability-polynomial constraints.

  • Two-stage, second-order explicit RK has one free tableau parameter.
  • Ralston’s α = 2/3 minimizes a specified leading local-error measure.
  • Order conditions and stability constraints can be imposed during coefficient search.
  • A tableau’s storage form can add constraints beyond its order conditions.
  • Q15 coefficients and floor rounding require evaluation of the implemented method.

Implicit RK cost on Cortex-M0+ collected 2026-09-25 08:28 CT, epoch 2, cycle 1500

SDIRK methods solve their stages in sequence. With a fixed step size and a reused Jacobian, their common diagonal coefficient allows the same linear system factorization to serve multiple stages, though nonlinear iterations still add work. Radau IIA solves coupled stage equations instead. Hairer’s Radau work identifies those nonlinear solves as a major implementation cost and documents cases where simplified Newton iterations converge slowly or fail at large step sizes. Rosenbrock and W methods replace nonlinear stage solves with linear solves; W methods can use an approximate Jacobian.

  • SDIRK has sequential implicit stages and can reuse a factorization when its linear system stays fixed.
  • Radau IIA couples its stages, making the nonlinear solve a central cost.
  • Rosenbrock and W methods require linear stage solves but no nonlinear stage iteration.
  • A fixed iteration limit bounds attempted work; it does not guarantee stage convergence.
  • For Q15 with floor rounding, solve accuracy and cycle cost need evaluation in the actual integer implementation.
  • Cortex-M0+ multiplication can take either 1 or 32 cycles, depending on the core configuration.

sources:
