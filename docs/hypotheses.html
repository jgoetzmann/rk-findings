How to read this

Each row pairs a machine-checkable predicate over per-cell statistics, for example slow.p3s4.heldout < slow.p4s4.heldout, with the mechanism and control the model recorded before the data could answer. p and s name an (order, stages) cell, the leading word picks the cost model, and heldout in a predicate is that cell elite's error on the held-out set, which selects elites and so is not a clean test set.

Verdicts come from code, never from the model. Once every cell a predicate names holds min_samples records, the predicate is evaluated against those cells' running statistics. d is Cohen's d; below 0.2 the verdict is inconclusive whichever way the comparison went, so a weak effect cannot be claimed. A predicate that names an empty cell is inconclusive too, because absence of evidence never refutes. n is the smallest record count among the named cells, and c is the cycle the verdict landed on (c123+ means proposed at cycle 123 and still open).

×N means the model posed that predicate N times over the run. The row shows the newest verdict and lists the id of every posing; mixed beside the verdict means those posings did not all get the same one.

Cost structure of implicit RK families on small MCUs collected 2026-09-23 19:05 CT, epoch 2, cycle 456

Fully implicit methods such as Radau IIA solve a coupled nonlinear system containing all stage values. A direct Newton step involves an sd-by-sd linear system for an s-stage method applied to a d-dimensional ODE. Simplified Newton can reuse one factorization per time step, but every retained Newton iteration still requires residual evaluations and a coupled solve. SDIRK and ESDIRK exploit a repeated diagonal coefficient so stages can be solved sequentially and the same d-by-d factorization can be reused. Their execution time nevertheless depends on the prescribed number of nonlinear and linear iterations unless both are statically bounded.

Rosenbrock methods replace each nonlinear stage solve with one linearized solve. When every stage uses the same diagonal coefficient, all stages share the matrix I-hγJ and can reuse its factorization. This gives a naturally fixed number of stage solves, although Jacobian construction, factorization, and solve accuracy remain significant costs. Published comparisons show that insufficiently accurate linear solves can destroy nominal order, while fixed truncated nonlinear iterations are common when exact Newton convergence is too expensive. On Cortex-M0+, Q15 coefficient products require careful implementation because MULS returns only the low 32 bits and may take either one or 32 cycles depending on the core configuration; the resulting shift or division, saturation, accumulation width, and floor-rounding behavior must therefore be included explicitly in any fixed-cycle cost model.

  • Radau IIA couples all stages into an sd-by-sd Newton system.
  • Simplified Newton permits one factorization per step but not one solve per step.
  • SDIRK and ESDIRK process stages sequentially and can reuse a d-by-d factorization.
  • Fixed Newton counts make runtime bounded but do not guarantee convergence or classical order.
  • Rosenbrock methods use one linear solve per stage instead of nonlinear stage iteration.
  • A common Rosenbrock diagonal coefficient permits factorization reuse across stages.
  • Loose linear-solver tolerances can reduce the observed order of Rosenbrock-Wanner methods.
  • Cortex-M0+ multiplication latency is implementation-dependent: one or 32 cycles.

Cortex-M0+ constant-multiply cost models collected 2026-09-23 18:14 CT, epoch 2, cycle 432

Arm’s Cortex-M0+ Technical Reference Manual specifies an implementation-configurable 32×32-bit MULS instruction that returns the low 32 bits. Depending on the selected multiplier implementation, MULS takes either 1 or 32 cycles; basic register shifts, additions, and subtractions are listed as one cycle under the manual’s zero-wait-state assumptions. Consequently, a fixed cycle budget cannot use a generic “Cortex-M0+ multiply cost”: it must identify the target silicon’s multiplier configuration and account separately for memory-system wait states. GCC reflects this distinction with cortex-m0plus and cortex-m0plus.small-multiply processor models, and its generated treatment of constant multiplication can vary with target and optimization settings.

Canonical signed-digit representation uses digits −1, 0, and 1 with no adjacent nonzero digits, minimizing the number of nonzero digits in the representation. A constant product can therefore be expressed as additions and subtractions of shifted operands; for example, runs of binary ones can be replaced by a difference of powers of two. This gives a useful initial instruction-count model for Q15 Runge, Kutta coefficients on a slow-multiplier implementation. Literature on multiplierless constant multiplication also shows that minimum CSD digit count does not necessarily minimize the complete computation: factored or graph-based shift-add forms and shared intermediate expressions can reduce operation count or dependency depth, especially when several tableau constants multiply related values. Exact Cortex-M0+ assessment therefore requires compiling or constructing each candidate sequence and counting its instructions and dependencies under the selected core and memory configuration.

  • Cortex-M0+ MULS latency is implementation-configurable: 1 or 32 cycles.
  • MULS computes a 32×32-bit product and retains the least-significant 32 bits.
  • Register add, subtract, and shift instructions are nominally one cycle with zero wait states.
  • The target MCU’s actual multiplier variant must be established before comparing MULS with shift-add sequences.
  • GCC exposes cortex-m0plus.small-multiply as a distinct CPU model.
  • CSD minimizes nonzero signed digits and forbids adjacent nonzero digits.
  • A CSD constant product maps directly to shifted operands combined by additions and subtractions.
  • Minimum CSD weight does not guarantee the fewest instructions or shortest dependency chain.

Numerical optimization of low-order Runge, Kutta tableaus collected 2026-09-23 17:27 CT, epoch 2, cycle 408

Classical order conditions constrain a Butcher tableau through polynomial equations associated with rooted trees, but often leave free coefficients. Those degrees of freedom can be selected using secondary objectives. Ralston analytically minimized specified truncation-error bounds for second-, third-, and fourth-order methods; the familiar two-stage, second-order Ralston scheme is one result. Modern software measures accuracy using the vector of leading rooted-tree error coefficients: NodePy exposes individual coefficients, principal-error norms, and exact or floating-point order checks.

RK-Opt turns tableau construction into a constrained numerical search over a prescribed stage count, order, and method class. It can minimize the principal error norm or maximize an SSP coefficient, optionally while fixing a previously optimized stability polynomial. Its authors emphasize that coefficient optimization is highly nonconvex, so multiple starting points may produce different feasible or locally optimal results. RootedTrees.jl supplies current symbolic infrastructure for generating order conditions. These sources optimize mathematical tableaus over real coefficients; they do not incorporate Q15 representability, floor-rounding bias, instruction count, or intermediate overflow into the stated objectives, so those properties require additional discrete constraints or evaluation after coefficient quantization.

  • Order conditions are polynomial equalities indexed by rooted trees.
  • Low-order explicit RK families retain free parameters after the target order is imposed.
  • Ralston selected free parameters by minimizing specified truncation-error bounds.
  • Principal error norm is the norm of the leading-order rooted-tree error coefficients.
  • RK-Opt searches by stage count, order, method class, bounds, and optional stability constraints.
  • RK-Opt supports accuracy and SSP objectives but documents a highly nonconvex search problem.
  • Optimal stability-polynomial search and realization as a full RK tableau can be separate steps.
  • Exact order verification is useful after replacing real coefficients with Q15-representable values.

Embedded RK pairs and quantized PI step control collected 2026-09-23 16:40 CT, epoch 2, cycle 384

Classical proportional step selection uses the current embedded-error estimate; the Gustafsson, Lundh, Söderlind PI approach also uses error history and was introduced to make adaptation more robust, particularly when stability limits the step size. In Q15, the controller cannot directly preserve the literature’s real-valued power laws: coefficient products require widened intermediates and explicit rescaling, while saturation and floor rounding can alter both the error estimate and the next-step decision. ARM’s CMSIS-DSP documentation confirms saturating Q15 multiplication but does not define a fixed-point embedded-RK or PI-controller implementation, so admissible step sizes, zero-error handling, rejection limits, scaling, and rounding semantics must be specified separately.

Quantization floors, underflow, and low-cost debiasing collected 2026-09-23 15:53 CT, epoch 2, cycle 360

Fixed-point ODE experiments show that arithmetic behavior can dominate formal Runge, Kutta order at low precision. Hopkins et al. report that default round-down multiplication harmed accuracy, while retaining wider intermediates longer improved results. In their explicit ODE tests, stochastic rounding reduced long-run trajectory and event-time errors; at very low precision it also prevented some updates from vanishing through underflow. Their reduced-cost experiments found little degradation when stochastic-rounding comparisons used six residual/random bits, while four or fewer bits became problem-dependent. Input dither was cheaper than rounding every multiplication and was effective in many, but not all, cases. For a Q15 implementation using floor rounding, every discarded nonzero remainder contributes a nonpositive local error, so the errors need not behave like unbiased noise. NASA’s integer-processing note independently identifies accumulated truncation bias and describes alternating roundoff direction as a low-cost debiasing mechanism. Q15 has a uniform spacing of 2^-15, so any stage increment smaller than one LSB can disappear; this creates a precision floor below which reducing the RK step may stop improving the trajectory. Wider Q31 intermediates with one final Q15 conversion reduce the number of biased quantization sites, but scaling must leave headroom because CMSIS-DSP fixed-point operations saturate on overflow. The cycle tradeoff is target-specific. Arm documents that Cortex-M0/M0+ designs use Armv6-M and that multiplier implementations may differ, so stochastic rounding, dither, or wider intermediates must be costed on the actual MCU rather than assigned an architecture-wide cycle count. Under a fixed budget, deterministic floor arithmetic should therefore be evaluated for signed drift, zeroed stage increments, and saturation separately from classical RK truncation error; cheap debiasing variants can be compared only after their random-number or state-update overhead is measured.

  • Floor rounding introduces one-sided local errors rather than zero-mean noise.
  • Q15 spacing is 2^-15; sub-LSB RK stage increments can quantize to zero.
  • Keeping products in wider precision until the final state update reduces quantization sites.
  • Stochastic rounding improved explicit fixed-point ODE results, including some underflow failures.
  • Six stochastic-rounding residual bits matched fuller implementations in the cited neuron tests; lower widths were problem-dependent.
  • Input dither is a cheaper, approximate alternative to per-multiply stochastic rounding.
  • Alternating roundoff direction is a deterministic method documented for reducing accumulated truncation bias.
  • Saturation and rounding are separate failure modes and require independent tests.

Production ODE integrator architecture and control collected 2026-09-23 15:06 CT, epoch 2, cycle 336

SciPy's solve_ivp defaults to RK45, a Dormand, Prince 5(4) pair implemented with NumPy arrays. Its Runge, Kutta core stores stage derivatives in an array shaped (stages + 1, state dimension), computes the embedded error by a weighted stage sum, and applies an RMS norm after componentwise scaling by atol + rtol·max(|y_old|, |y_new|). RK45 defaults to rtol=1e-3 and atol=1e-6. Accepted and rejected steps use a proportional controller with safety factor 0.9, shrink floor 0.2, growth ceiling 10, and exponent -1/(error-estimator order + 1); growth is suppressed immediately after a rejection. This design relies on floating-point norms, powers, dynamic step sizes, rejection loops, and several full-state work arrays, all of which must be explicitly bounded or replaced for a fixed-cycle Q15 implementation.

Boost.Odeint separates the numerical method from State, Algebra, Operations, and Resizer policies. Explicit steppers can therefore operate on fixed-size std::array-like storage and custom scalar or elementwise operations; controlled Runge, Kutta steppers retain derivative, error, candidate-state, and, for FSAL methods, new-derivative temporaries. Its default checker uses the maximum componentwise normalized error, with denominator eps_abs + eps_rel·(a_x|x| + a_dxdt|dt·dxdt|); defaults are eps_abs=eps_rel=1e-6 and a_x=a_dxdt=1. CVODE is not a Runge, Kutta implementation: it uses variable-step, variable-order Adams, Moulton or BDF formulas, abstract N_Vector storage, predictor-corrector history, and a weighted RMS norm with weights 1/(rtol|y_i|+atol_i). These production designs show three distinct choices relevant to a bounded fixed-point search: contiguous stage-major RK workspace with RMS control, policy-configurable fixed-size storage with max-norm control, and history-based multistep storage with WRMS control.

Long-run roundoff and truncation error in low-precision ODE solvers collected 2026-09-23 14:20 CT, epoch 2, cycle 312

ODE error analyses predict a crossover as the step size decreases: truncation error initially falls, but the growing number of arithmetic operations eventually makes roundoff dominant. Under an idealized independent, zero-mean rounding model, accumulated computational error commonly scales like the square root of the step count, equivalently as h^(-1/2) over a fixed interval. Worst-case coherent accumulation can instead scale as h^(-1). A posteriori analysis further shows that these errors are multiplied by problem-dependent stability factors, which can grow rapidly for sensitive or chaotic systems. Consequently, more steps or a higher-order method need not improve the final result after the arithmetic-error floor is reached.

Those probabilistic cancellation results do not directly apply to Q15 floor rounding. Floor-directed quantization is biased, and its errors may be correlated with the state and RK stages, so systematic drift closer to linear accumulation is possible. Fixed-point ODE experiments report that truncated constants and arithmetic conversions introduce errors that accumulate, while stochastic rounding reduces bias and avoids stagnation. RK implementation details also matter: internal stage perturbations can be strongly amplified even when the method has acceptable classical stability. For a fixed-cycle Cortex-M0+ search, the relevant comparison is therefore total propagated error at the permitted step count, including coefficient quantization, stage-level floor errors, overflow and stagnation, not truncation order alone.

  • Truncation error decreases with step size, while accumulated roundoff eventually increases.
  • Independent zero-mean roundoff gives an expected h^(-1/2), or square-root-of-step-count, contribution.
  • Coherent or biased errors can approach h^(-1), or linear-in-step-count, accumulation.
  • Floor rounding is biased, so zero-mean random-walk models are not automatically valid for Q15.
  • Problem-dependent stability factors govern how local arithmetic errors affect the final state.
  • RK stage representations can amplify internal rounding perturbations within each step.
  • Quantized coefficients and conversions can create persistent error in fixed-point ODE implementations.
  • Stochastic rounding can reduce bias and stagnation, but adds implementation cost and nondeterminism.

RK stability per cycle and implicit crossover collected 2026-09-23 13:34 CT, epoch 2, cycle 288

For an explicit s-stage Runge, Kutta method, linear stability is governed by a degree-at-most-s polynomial approximating exp(z), and stability requires |R(hλ)| ≤ 1 for relevant eigenvalues λ. At order three, moving from five to six stages adds polynomial and tableau freedom that can enlarge or reshape the stability region, but it does not by itself guarantee lower nonlinear truncation error. Stability-polynomial optimization is spectrum-dependent, and published work compares methods of unequal stage count using effective stable step size per stage, h/s, because per-step work normally grows with the number of stages. Thus the six-stage hypothesis is supported only if its larger usable step or smaller error constant offsets its extra stage under the actual cycle model and held-out spectra.

  • The relevant stability metric is coverage of the scaled spectrum hλ, not stability-region area alone.
  • An extra stage can enlarge or reshape an order-three stability polynomial but does not guarantee lower truncation error.
  • Under a fixed budget, compare stable progress per cost, such as admissible h divided by measured cycles, rather than admissible h alone.

Deterministic low-precision and energy-aware integration collected 2026-09-23 12:46 CT, epoch 2, cycle 264

Recent literature offers three complementary approaches, but little direct evidence for Q15 Runge, Kutta on Cortex-M0+. Mixed-precision RKC research shows that naïvely lowering stage precision can reduce convergence order and cap attainable accuracy. Its redesigned schemes retain selected high-precision evaluations for accuracy while performing stability-oriented stages in low precision. Separately, formal fixed-point optimization research propagates numerical errors to select variable-specific formats satisfying an accuracy bound, although its reported implementation targets FPGA high-level synthesis rather than microcontrollers or a uniform Q15 format.

Hard real-time research on implicit MPC demonstrates that execution-time guarantees depend on the realized program, compiler, hardware, input-dependent control flow, and initial processor state; under stated assumptions, finitely many execution-equivalent cases can determine exact WCET. For structure preservation, 2025 work derives explicit Runge, Kutta formulas whose energy error has higher asymptotic order than their solution error. These fixed-stage methods produced smaller energy errors than comparable conventional RK methods over moderate and moderately long simulations, but they preserve energy only approximately. Relaxation RK can enforce conservation or dissipation of a convex functional, while requiring an additional scalar algebraic solve each step. None of these studies directly establishes behavior under Q15 floor rounding, so their accuracy and conservation results do not transfer without fixed-point error analysis and target-level timing measurements.

  • Naïve low-precision RK stage evaluation can lower convergence order and impose an accuracy floor.
  • Mixed-precision RKC confines high precision to one or two accuracy-critical function evaluations in the presented earliest- and second-order schemes.
  • Formal range-and-error propagation can derive per-variable fixed-point formats with stated output-accuracy guarantees.
  • WCET is a property of the compiled implementation and hardware state, not solely of the numerical algorithm.
  • Explicit pseudo-energy-preserving RK methods have fixed stage counts but provide approximate, not exact, energy preservation.
  • Higher pseudo-energy-preserving order generally requires additional RK stages.
  • Relaxation RK retains the base RK structure but adds a scalar equation solve whose work must be bounded for hard real-time use.
  • The consulted studies do not directly test Cortex-M0+, uniform Q15 arithmetic, or floor rounding.

Cortex-M0+ fixed-point constant multiplication collected 2026-09-23 11:52 CT, epoch 2, cycle 240

Arm specifies two implementation options for the Cortex-M0+ multiplier. MULS computes the low 32 bits of a 32-by-32-bit product and takes either one cycle with the fast array multiplier or 32 cycles with the small iterative multiplier. The choice is made by the chip implementer, so cycle models must use the selected microcontroller’s documentation rather than assuming that every Cortex-M0+ has the same multiplication cost. For Q15 operands, the exact signed product fits in 32 bits; an arithmetic right shift by 15 then performs the binary rescaling. ARMv6-M arithmetic right shift copies the sign bit and discards low bits, which implements floor division by a power of two for two's-complement values and therefore directly matches floor rounding.

  • Cortex-M0+ MULS returns the least-significant 32 bits of a 32-by-32-bit product.
  • The configurable multiplier is either a one-cycle array implementation or a 32-cycle iterative implementation.
  • The iterative multiplier can be abandoned and restarted when an interrupt is taken.
  • A signed Q15-by-Q15 product fits exactly in a signed 32-bit intermediate.
  • ASR by 15 supplies floor-rounded Q15 rescaling, including for negative products.
  • CSD represents constants with digits from {-1, 0, 1} and no adjacent nonzero digits.
  • CSD minimizes the number of nonzero signed digits, but it does not necessarily produce the minimum-depth or minimum-operation adder graph.
  • Shift-add constant multiplication replaces each nonzero signed digit with a shifted add or subtract.
