About the project ↗

The hypothesis ledger: predicates the planning model committed to before the data could answer them, each resolved by code. Open a row for the statement, the proposed mechanism and the control that would have shown the mechanism wrong. Below the ledger are the model's readings of the archive and its literature digests.

How to read this

Each row pairs a machine-checkable predicate over per-cell statistics, for example slow.p3s4.heldout < slow.p4s4.heldout, with the mechanism and control the model recorded before the data could answer. p and s name an (order, stages) cell, the leading word picks the cost model, and heldout in a predicate is that cell elite's error on the held-out set, which selects elites and so is not a clean test set.

Verdicts come from code, never from the model. Once every cell a predicate names holds min_samples records, the predicate is evaluated against those cells' running statistics. d is Cohen's d; below 0.2 the verdict is inconclusive whichever way the comparison went, so a weak effect cannot be claimed. A predicate that names an empty cell is inconclusive too, because absence of evidence never refutes. n is the smallest record count among the named cells, and c is the cycle the verdict landed on (c123+ means proposed at cycle 123 and still open).

×N means the model posed that predicate N times over the run. The row shows the newest verdict and lists the id of every posing; mixed beside the verdict means those posings did not all get the same one.

Rounding in fixed-point Runge, Kutta integration collected 2026-09-27 18:30 CT, epoch 2, cycle 2100

Cortex-M0+ multiplication costs and signed-digit constants collected 2026-09-26 19:00 CT, epoch 2, cycle 1900

Arm specifies two Cortex-M0+ multiplier implementations: MULS takes either 1 cycle or 32 cycles and returns only the low 32 bits. In its zero-wait-state timing table, shifts, adds, and subtracts each take 1 cycle. The multiplier variant therefore changes the cycle cost of fixed-point Runge, Kutta coefficients: a short shift-add sequence can beat a 32-cycle multiply, while it may cost more than a single-cycle multiply. NXP documents a Cortex-M0+ implementation with the 32-cycle variant.

Canonical signed digit (CSD) representation minimizes the number of nonzero signed digits in a constant, which can reduce the terms in a shift-add multiplication. That digit count alone is not an instruction count: Cortex-M0+ shifts and additions are separate instructions, and loads and register use also affect a compiled sequence. GCC recognizes cortex-m0plus.small-multiply and its published tests show different choices for constants and optimization goals. For Q15 floor rounding, Arm specifies that arithmetic right shift rounds negative values toward negative infinity; this gives the intended floor after a full-precision product is formed, provided intermediate arithmetic has not overflowed.

  • MULS costs 1 or 32 cycles according to the implemented multiplier.
  • MULS retains only the low 32 bits of a 32-by-32 product.
  • Cortex-M0+ shifts, adds, and subtracts are listed as 1-cycle instructions under zero wait states.
  • CSD minimizes nonzero digits, but compiled shift-add cost depends on the instruction sequence.
  • ASR rounds signed division by a power of two toward negative infinity.
