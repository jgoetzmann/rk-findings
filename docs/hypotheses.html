About the project ↗

The hypothesis ledger: predicates the planning model committed to before the data could answer them, each resolved by code. Open a row for the statement, the proposed mechanism and the control that would have shown the mechanism wrong. Below the ledger are the model's readings of the archive and its literature digests.

How to read this

Each row pairs a machine-checkable predicate over per-cell statistics, for example slow.p3s4.heldout < slow.p4s4.heldout, with the mechanism and control the model recorded before the data could answer. p and s name an (order, stages) cell, the leading word picks the cost model, and heldout in a predicate is that cell elite's error on the held-out set, which selects elites and so is not a clean test set.

Verdicts come from code, never from the model. Once every cell a predicate names holds min_samples records, the predicate is evaluated against those cells' running statistics. d is Cohen's d; below 0.2 the verdict is inconclusive whichever way the comparison went, so a weak effect cannot be claimed. A predicate that names an empty cell is inconclusive too, because absence of evidence never refutes. n is the smallest record count among the named cells, and c is the cycle the verdict landed on (c123+ means proposed at cycle 123 and still open).

×N means the model posed that predicate N times over the run. The row shows the newest verdict and lists the id of every posing; mixed beside the verdict means those posings did not all get the same one.

SciPy’s solve_ivp defaults to an adaptive RK45 5(4) pair. Its explicit Runge, Kutta code stores stage derivatives in an array shaped (stages + 1, state size), scales each component’s estimated error by absolute tolerance plus relative tolerance times the larger of the old and new state magnitudes, and accepts a step when the scaled RMS error is below one. Its step-size controller uses a 0.9 safety factor and limits size changes. Boost odeint lets callers choose state containers, including fixed-size std::array. Its controlled Runge, Kutta stepper uses the maximum componentwise scaled error and changes step size according to documented thresholds and bounds.

  • SciPy RK45 defaults: relative tolerance 1e-3; absolute tolerance 1e-6.
  • SciPy’s RK workspace has one state-sized row per stage plus an endpoint derivative.
  • Boost controlled Runge, Kutta uses a maximum norm; SciPy uses an RMS norm.
  • CVODE uses weighted RMS error and retains multistep history rather than Runge, Kutta stages.
  • The cited controllers retry failed steps, so their execution cost varies by step.

Cortex-M0+ multiplication costs and signed-digit constants collected 2026-09-26 19:00 CT, epoch 2, cycle 1900

Arm specifies two Cortex-M0+ multiplier implementations: MULS takes either 1 cycle or 32 cycles and returns only the low 32 bits. In its zero-wait-state timing table, shifts, adds, and subtracts each take 1 cycle. The multiplier variant therefore changes the cycle cost of fixed-point Runge, Kutta coefficients: a short shift-add sequence can beat a 32-cycle multiply, while it may cost more than a single-cycle multiply. NXP documents a Cortex-M0+ implementation with the 32-cycle variant.

Canonical signed digit (CSD) representation minimizes the number of nonzero signed digits in a constant, which can reduce the terms in a shift-add multiplication. That digit count alone is not an instruction count: Cortex-M0+ shifts and additions are separate instructions, and loads and register use also affect a compiled sequence. GCC recognizes cortex-m0plus.small-multiply and its published tests show different choices for constants and optimization goals. For Q15 floor rounding, Arm specifies that arithmetic right shift rounds negative values toward negative infinity; this gives the intended floor after a full-precision product is formed, provided intermediate arithmetic has not overflowed.

  • MULS costs 1 or 32 cycles according to the implemented multiplier.
  • MULS retains only the low 32 bits of a 32-by-32 product.
  • Cortex-M0+ shifts, adds, and subtracts are listed as 1-cycle instructions under zero wait states.
  • CSD minimizes nonzero digits, but compiled shift-add cost depends on the instruction sequence.
  • ASR rounds signed division by a power of two toward negative infinity.

Runge, Kutta stability under a cycle budget collected 2026-09-25 22:41 CT, epoch 2, cycle 1750

For an explicit Runge, Kutta method with s stages, linear stability is governed by a polynomial of degree at most s. Order p fixes its earliest p+1 coefficients. Thus a two-stage order-2 method and a four-stage order-4 method have fixed stability polynomials, while five- or six-stage methods of lower order have coefficients available to extend stability over a chosen spectrum. Published optimization work uses those extra stages to permit larger stable steps; it does not establish that the larger region gives lower error at a fixed cost. [Ketcheson and Ahmadia](https://numerics.kaust.edu.sa/papers/stability_polynomials/stability_polynomials_2012.html) [Many-Stage Optimal Stabilized Runge, Kutta Methods](https://link.springer.com/article/10.1007/s10915-024-02478-5)

The useful comparison is the stable and accurate time advanced per measured cycle, including every stage and coefficient operation. Explicit stability regions are bounded, so sufficiently stiff modes can force more steps than accuracy alone requires. Implicit methods can then pay for their stage solves by taking fewer steps, but that crossover depends on the system and implementation: implicit stages require solving coupled equations, commonly through Newton linear systems. For Q15 with floor rounding, the polynomial analysis is a screening tool; the implemented recurrence also needs stability and error measurements. [Hairer and Wanner](https://www.unige.ch/~hairer/preprints/coimbra.pdf) [Butcher](https://www.math.auckland.ac.nz/~butcher/ODE-book-2008/Tutorials/IRK.pdf)

  • Extra stages can enlarge stability without increasing formal order.
  • The useful stability region depends on the problem’s eigenvalue spectrum.
  • Compare error and stable time advanced per measured cycle.
  • Implicit methods pay when fewer required steps outweigh their solve cost.
  • Check Q15 floor-rounded behavior in the implemented recurrence.

Production ODE integrator layouts and error control collected 2026-09-25 21:21 CT, epoch 2, cycle 1725

SciPy’s solve_ivp defaults to RK45, an embedded 5(4) method. Its implementation stores stage derivatives as rows of an array shaped (stages + 1, state size), reuses the endpoint derivative, and tests the RMS norm of the embedded error scaled by atol + rtol × max(|old state|, |new state|). The default tolerances are rtol = 1e-3 and atol = 1e-6. Its step controller uses a 0.9 safety factor and bounds changes in step size.

Boost odeint permits state containers such as std::array and std::vector through its algebra and operations interfaces. Its default controlled Runge, Kutta checker uses the largest component error, scaled by absolute tolerance plus relative tolerance times the old state and step-scaled old derivative; both tolerances default to 1e-6. CVODE uses variable-step, variable-order Adams or BDF multistep methods rather than Runge, Kutta. It uses a weighted RMS error norm, and its serial N_Vector stores a length and a pointer to contiguous state data.

These libraries’ error tests, stored work arrays, and step rejection rules affect their evaluation counts and memory costs. Their adaptive results therefore do not by themselves determine which Runge, Kutta order or stage count has lower error under a fixed Q15 cycle budget.
