How to read this

Each row pairs a machine-checkable predicate over per-cell statistics, for example slow.p3s4.heldout < slow.p4s4.heldout, with the mechanism and control the model recorded before the data could answer. p and s name an (order, stages) cell, the leading word picks the cost model, and heldout in a predicate is that cell elite's error on the held-out set, which selects elites and so is not a clean test set.

Verdicts come from code, never from the model. Once every cell a predicate names holds min_samples records, the predicate is evaluated against those cells' running statistics. d is Cohen's d; below 0.2 the verdict is inconclusive whichever way the comparison went, so a weak effect cannot be claimed. A predicate that names an empty cell is inconclusive too, because absence of evidence never refutes. n is the smallest record count among the named cells, and c is the cycle the verdict landed on (c123+ means proposed at cycle 123 and still open).

×N means the model posed that predicate N times over the run. The row shows the newest verdict and lists the id of every posing; mixed beside the verdict means those posings did not all get the same one.

Rounding modes in fixed-point ODE solvers collected 2026-09-24 13:03 CT, epoch 2, cycle 984

Fixed-point ODE experiments show that rounding policy can materially change long-run trajectories. In tests involving four explicit solvers and an Izhikevich neuron model, stochastic rounding of multiplication results produced smaller spike-timing errors than round-to-nearest or discarded-bit rounding. Six random bits were sufficient in those experiments, while 16-bit arithmetic still suffered from overflow and underflow. The authors also measured about 30% overhead when replacing round-to-nearest with software stochastic rounding in an RK2 midpoint implementation; execution speed was governed largely by the pseudorandom-number generator.

These findings bear directly on Q15 integration with floor rounding. Floor is directionally biased, unlike stochastic rounding, whose expected rounded value equals the unquantized value. It is also distinct from simple signed truncation: an arithmetic right shift of a negative two's-complement product normally behaves like floor, whereas a conversion that truncates toward zero does not. CMSIS-DSP documents saturating Q15 operations and wider intermediate products followed by shifts, so the exact locations of narrowing shifts and saturation are part of the numerical method, not merely implementation details. Retaining wide products or accumulators until a stage sum is complete reduces the number of quantization events, while stochastic rounding introduces PRNG, masking, shifting, and addition work that may conflict with a fixed Cortex-M0+ cycle budget.

  • Directed floor rounding introduces a negative one-sided quantization error whenever a result is not exactly representable.
  • For negative values, arithmetic right shift implements floor-like behavior rather than truncation toward zero.
  • Stochastic rounding is unbiased in expectation and can prevent small updates from being lost systematically.
  • Fixed-point ODE tests found stochastic rounding more accurate than round-to-nearest and discarded-bit rounding across several explicit solvers.
  • Six random residual bits were sufficient in the cited neuron-model experiments, but this is empirical rather than universal.
  • The cited RK2 benchmark measured roughly 30% software overhead for stochastic rounding relative to round-to-nearest.
  • Wide intermediate products and deferred narrowing reduce how often rounding error enters an RK step.
  • Q15 saturation creates nonlinear error distinct from rounding error, so overflow counts and rounding bias should be evaluated separately.

Production ODE integrator architecture collected 2026-09-24 12:07 CT, epoch 2, cycle 960

SciPy’s solve_ivp defaults to the explicit Dormand, Prince RK45 pair with rtol=1e-3 and atol=1e-6. Its implementation stores stage derivatives in a NumPy array K of shape (stages+1, state dimension), forms the embedded error by a weighted combination of those rows, and evaluates an RMS norm after componentwise scaling by atol + rtol·max(|y_old|,|y_new|). The proportional controller uses safety 0.9, limits each change to [0.2,10], and prevents immediate growth after a rejected step. Thus its acceptance test and controller entail reductions, division, powers, and retry-dependent execution rather than a fixed cycle count.

Boost.Odeint separates the numerical algorithm from state storage through templated state, algebra, and operation types; supported states include std::array and std::vector, and custom fixed-size types can supply their own algebra. Its default RK checker scales each component against eps_abs + eps_rel·(a_x|x| + a_dxdt|dt·dxdt|), with a_x=a_dxdt=1 and default checker tolerances of 1e-6, then uses the algebra’s infinity-norm reduction. This design is more amenable to compile-time fixed storage than SciPy’s, although the controlled stepper still accepts, rejects, and resizes steps dynamically.

CVODE is not a Runge, Kutta implementation: it uses variable-step, variable-order Adams methods through order 12 or BDF through order 5. It operates through the abstract N_Vector interface; the serial implementation contains a length and pointer to a contiguous sunrealtype array, while custom vector backends are supported. Error-like quantities use a weighted RMS norm with weights 1/(rtol·|y_i|+atol_i). Defaults include automatic initial-step estimation, no positive minimum step, maximum step infinity, up to 500 internal steps per requested output, and Newton nonlinear iteration by default. Across all three libraries, conventional production control depends on scaled vector reductions and variable work, so a Q15 implementation with floor rounding and a fixed cycle budget would need explicitly bounded storage, arithmetic, reductions, and retry policy rather than directly inheriting these controllers.

  • SciPy RK45 stores all stage derivatives in a (stages+1) by n NumPy array.
  • SciPy uses an RMS norm of the embedded error divided by atol + rtol·max(|y_old|,|y_new|).
  • SciPy RK control uses safety 0.9 with step-change bounds 0.2 and 10.
  • Boost.Odeint decouples steppers from storage through state, algebra, and operation templates.
  • Boost’s default controlled-RK criterion includes both state magnitude and dt times derivative magnitude.
  • Boost controlled steppers reduce the scaled component errors with an infinity norm.
  • CVODE uses variable-order Adams or BDF multistep formulas, not Runge, Kutta formulas.
  • CVODE uses WRMS error tests with component weights 1/(rtol·|y_i|+atol_i).

RK stability under fixed cycle budgets collected 2026-09-24 11:17 CT, epoch 2, cycle 936

For the scalar test equation y′=λy, an explicit s-stage Runge, Kutta method has a polynomial stability function, so its stable step is bounded by the portion of the spectrum mapped into |R(hλ)|≤1. Classical low-stage methods provide only short negative-real-axis intervals: approximately 2 for Euler and second-order RK, 2.51 for third-order RK, and 2.79 for classical RK4. Stabilized explicit methods instead spend additional stages enlarging selected parts of the stability region; Chebyshev constructions can make the negative-real interval grow proportionally to s², although damping and internal amplification become important. Optimization for hyperbolic spectra similarly shows that merely adding stages need not improve throughput when both stable step and execution cost grow linearly with stage count.

Under a fixed cycle budget, an implicit method pays only when the explicit method's stability-imposed substeps cost more than the nonlinear or linear solves needed by the implicit step, while the implicit step remains accurate enough to exploit its larger stability region. A-stability alone is insufficient for strongly damped modes: L-stable methods such as Radau IIA are designed to suppress them, whereas stiff problems can also cause order reduction tied to stage order. These comparisons assume conventional arithmetic. Low-precision research reports that naïvely reducing precision in stabilized RK stages can reduce convergence order and cap attainable accuracy, while many-stage work explicitly controls internal roundoff amplification; therefore Q15 floor arithmetic requires implementation-specific stability and error measurements rather than relying solely on real-arithmetic regions.

  • Explicit RK stability is bounded because its stability function is a polynomial.
  • Classical RK4 extends the negative-real stability interval only modestly relative to its four-stage cost.
  • Chebyshev-stabilized explicit RK can obtain negative-real stability intervals proportional to the square of the stage count.
  • Extra stages are beneficial only when stable-step growth exceeds their cycle cost for the relevant spectrum.
  • Implicit break-even depends on solve cost, explicit stability substepping, and the accuracy-limited step size.
  • L-stability matters when very stiff modes must be strongly damped.
  • Stiff order reduction can limit the practical benefit of an otherwise stable implicit RK method.
  • Naïve low-precision stages can lower convergence order and impose an accuracy floor.

Long-run finite-precision ODE error collected 2026-09-24 10:25 CT, epoch 2, cycle 912

Probabilistic analyses of deterministic ODE solvers model accumulated roundoff as random perturbations. Mosbach and Turner derive trajectory distributions depending on time, step size, and arithmetic precision, and demonstrate the effect for Euler, RK4, VODE, and RADAU5. The literature also reports the familiar error crossover: decreasing the step initially reduces truncation error, but eventually the larger operation count makes accumulated roundoff dominant. Thus, at a fixed final time, increasing the step count need not improve the computed solution indefinitely.

Modern backward-error results explain why unbiased stochastic rounding can accumulate more slowly than worst-case deterministic bounds suggest. Connolly, Higham, and Mary prove zero mean and mean independence for stochastic-rounding errors and obtain earliest-order probabilistic bounds proportional to the square root of the operation count rather than the operation count. These conclusions do not transfer directly to Q15 floor rounding: floor quantization is directionally biased, fixed-point error is absolute rather than relative, and repeated sub-LSB increments can be systematically lost. Consequently, random-walk error models can be useful comparison cases, but a floor-rounded implementation also requires a deterministic bias term whose propagation depends on the ODE dynamics and the exact ordering of each Runge, Kutta stage.

  • Truncation error falls with step size while accumulated arithmetic error generally grows with step count.
  • The resulting total-error curve can have a minimum at a nonzero step size.
  • Probabilistic ODE analysis predicts distributions of long-time trajectories rather than only worst-case bounds.
  • Square-root operation-count bounds require zero-mean or comparable statistical assumptions.
  • Stochastic rounding has a proved zero-mean property and can avoid small-increment stagnation.
  • Floor rounding is biased, so unbiased random-walk models are not directly valid for Q15 execution.
  • Fixed-point quantization supplies an absolute error scale set by the LSB.
  • Arithmetic ordering can materially change finite-precision Runge, Kutta error.

Deterministic low-precision and energy-aware integration collected 2026-09-24 09:41 CT, epoch 2, cycle 888

Work motivated by hard real-time optimal control confirms a tension between integration accuracy and bounded computation: Lahr et al. report that fixed grids can incur control-dependent integration error, whereas adaptive grids can exceed prescribed sampling times. Energy-preserving research offers several alternatives, but commonly introduces costs that complicate a fixed cycle budget. Myhr and Eidnes construct a fourth-order derivative-free discrete-gradient method with exact earliest-integral preservation, yet it remains implicit and uses Newton iterations. Other recent schemes obtain exact or high-order energy conservation through linear solves, relaxation parameters, or problem-specific Hamiltonian structure. Explicit pseudo-energy-preserving RK methods instead satisfy energy conditions only through a finite order, suggesting a fixed-stage option when exact conservation is too costly. The consulted literature does not analyze whether conservation claims survive asymmetric Q15 floor rounding, so those properties require fixed-point-specific verification.

  • Mixed-precision RK speedups are hardware- and kernel-dependent, not implied by reduced precision alone.
  • Truncating low-precision RK coefficients can materially change the stability region.
  • Fixed grids provide predictable work but may have control-dependent discretization error.
  • Exact discrete-gradient conservation generally requires an implicit solve.
  • Linearly implicit and relaxation methods reduce some nonlinear-solve costs but still add variable or nontrivial work.
  • Pseudo-energy-preserving explicit RK methods trade exact conservation for fixed-stage explicit execution.
  • The consulted studies do not cover Cortex-M0+, Q15 saturation, or systematic floor rounding.

Embedded RK control under Q15 floor arithmetic collected 2026-09-24 08:52 CT, epoch 2, cycle 864

Bogacki, Shampine 3(2) and Dormand, Prince 5(4) estimate local error by forming two different-order solutions from shared Runge, Kutta stages. Bogacki, Shampine uses four stages and has the FSAL property, permitting roughly three derivative evaluations after a successful step; Dormand, Prince uses seven stages and FSAL, permitting six. These savings depend on retaining the final derivative for the next accepted step. A rejected step cannot obtain the same reuse pattern, so a fixed cycle budget must account for rejection policy as well as nominal stage count.

Control-theoretic treatments model the solver and step-size controller as a coupled dynamical system. PI/PID controllers use present and previous error estimates to smooth step changes and reduce instability associated with purely proportional control. In Q15, both the embedded error and controller state are quantized; division, fractional powers, saturation, minimum-step rules, and accepted-step history therefore require explicit integer definitions. ARM CMSIS-DSP documents saturating Q15 operations, format-changing shifts, and normalized fixed-point division, but it does not supply an embedded-RK controller or establish floor rounding as a universal convention.

Reduced-precision ODE studies show that rounding mode materially changes accumulated solver error: stochastic rounding outperformed deterministic round-to-nearest in the reported neural-ODE experiments. Floor rounding is different from both and introduces a one-sided quantization error except at exactly representable results. Consequently, floating-point RK and PI-controller analyses do not by themselves characterize a floor-rounded Q15 implementation; its integer coefficient encodings, intermediate widths, saturation points, error-norm quantization, and step-size state transitions must be treated as part of the numerical method.

  • Bogacki, Shampine is an embedded 3(2) pair with four stages and FSAL reuse.
  • Dormand, Prince is an embedded 5(4) family; its common seven-stage member uses FSAL.
  • FSAL reduces accepted-step derivative evaluations but does not eliminate rejection overhead.
  • PI/PID step controllers use error history and are dynamical systems coupled to the integrator.
  • Quantizing the error estimate can create dead zones and repeated controller states.
  • Q15 division may return a normalized quotient plus a separate binary shift.
  • CMSIS-DSP distinguishes saturating arithmetic from unsaturated wider accumulation.
  • Floor rounding has directional bias and is not covered by results for round-to-nearest or stochastic rounding.

Cortex-M0+ constant multiplication and CSD collected 2026-09-24 07:59 CT, epoch 2, cycle 840

Arm specifies two implementation-time multiplier options for Cortex-M0+: a fast single-cycle array multiplier and a smaller 32-cycle iterative multiplier. MULS computes the low 32 bits of a 32×32-bit product and therefore provides enough width for a signed Q15×Q15 product before rescaling. In a zero-wait-state system, ADD, SUB, and register shifts are one-cycle instructions, while MULS takes either 1 or 32 cycles. Consequently, shift-add constant multiplication can be substantially cheaper than MULS on the small-multiplier variant but may be more expensive on the fast variant; exact costs also depend on generated code, constant materialization, register moves, spills, and memory wait states.

  • Cortex-M0+ multiplier choice is an implementation-time property of the particular MCU, not an architectural constant.
  • MULS latency is 1 or 32 cycles in Arm's zero-wait-state timing table.
  • MULS returns the least-significant 32 bits of a 32×32-bit product.
  • Q15 multiplication naturally forms a 2.30 intermediate before conversion back to 1.15.
  • An arithmetic right shift by 15 implements floor division by 32768 for signed two's-complement intermediates when the target's ASR semantics are used.
  • CSD represents a constant with digits -1, 0, and 1, no adjacent nonzero digits, and the minimum number of nonzero signed digits.
  • Each CSD nonzero digit becomes a shifted positive or negative copy of the input, combined by additions or subtractions.
  • Minimum CSD digit count does not by itself guarantee the shortest Cortex-M0+ instruction sequence because intermediate reuse, register pressure, constant loading, and scheduling also matter.

Numerical optimization of low-order Runge, Kutta tableaus collected 2026-09-24 07:11 CT, epoch 2, cycle 816

Runge, Kutta construction is naturally a constrained polynomial problem: coefficients must satisfy one rooted-tree condition for every tree through the requested order, while remaining degrees of freedom may be selected to reduce principal truncation-error norms, enlarge a stability region, impose SSP or low-storage structure, or balance several such objectives. NodePy and RootedTrees.jl generate and evaluate these conditions from rooted trees. RK-Opt separates optimization of the stability polynomial from optimization of tableau coefficients and uses numerical optimization, including multistart searches, for prescribed stage counts and orders. Published method searches likewise treat the unsatisfied next-order conditions as an error vector and minimize a norm of that vector subject to order and stability constraints.

  • Order conditions are polynomial equalities indexed by rooted trees.
  • Extra stages or unconstrained coefficients create free parameters after the target-order conditions are imposed.
  • A principal error norm is formed from residuals of the next-order rooted-tree conditions.
  • Minimizing an error norm and maximizing a stability measure are distinct, potentially competing objectives.
  • RK-Opt supports separate searches for stability polynomials and for tableau coefficients of fixed order and stage count.
  • Multistart or randomized searches are used because the constrained coefficient problem is nonlinear and has many local solutions.
  • Low-storage constraints can be added to the standard order conditions; recent work reports both analytic low-order families and numerical selection among them.
  • Classical order and error constants do not capture arithmetic perturbations: internal-error amplification depends materially on the implementation form.

Quantized Runge, Kutta arithmetic collected 2026-09-24 06:22 CT, epoch 2, cycle 792

Fixed-point ODE studies report a characteristic error floor: reducing the timestep initially lowers discretization error, but eventually increases total error because more quantized operations accumulate. Accuracy depends not only on the Runge, Kutta tableau but also on expression ordering, intermediate widths, scaling, overflow handling, and the points at which products are requantized. Gill’s early RK4 implementation explicitly reorganized the calculation to improve attainable finite-word accuracy while minimizing storage. More recent neural-ODE experiments likewise find that implementation details materially affect fixed-point results.

Floor rounding is directed toward negative infinity, so every inexact Q15 quantization has an error in [-2^-15, 0), creating a one-sided local bias rather than zero-mean noise. Repetition across RK stages and timesteps can therefore produce systematic drift. Published low-precision RK analysis shows that deterministic round-to-nearest can stagnate at sufficiently small timesteps, whereas stochastic rounding makes leading errors zero-mean and substantially weakens their accumulation; fixed-point neural-ODE experiments found stochastic rounding more accurate than round-to-nearest across several explicit solvers. On an MCU, however, stochastic rounding requires random bits and comparison/selection work. CMSIS-DSP confirms the relevant implementation choices for Q15/Q31, fractional-width conversions, shifts, saturating operators, and optional nonsaturating accumulation, so accumulator width and the exact narrowing locations must be treated as part of the numerical method under a fixed cycle budget.

  • Q15 floor quantization contributes an error from -2^-15 inclusive to 0 exclusive at each inexact narrowing.
  • Floor rounding creates a negative local bias; it is not equivalent to unbiased round-to-nearest or stochastic rounding.
  • Smaller timesteps can worsen fixed-point results after quantization error overtakes truncation error.
  • RK accuracy changes with expression ordering, intermediate precision, scaling, and requantization placement.
  • Stochastic rounding suppresses stagnation and changes accumulated error from systematic to predominantly zero-mean behavior.
  • Experiments on fixed-point neural ODEs found stochastic rounding more accurate than round-to-nearest across multiple explicit solvers.
  • Stochastically rounding constants and the timestep on every integration step improved spike timing in most reported neuron tests.
  • CMSIS-DSP Q15/Q31 facilities distinguish saturating arithmetic from nonsaturating accumulation; either choice changes overflow behavior.

Implicit RK cost under fixed iteration budgets collected 2026-09-24 05:32 CT, epoch 2, cycle 768

SDIRK methods reduce an implicit Runge, Kutta step to a sequence of stage-sized nonlinear problems. Because every diagonal coefficient is identical, simplified-Newton implementations can reuse the same iteration matrix and factorization across stages. Radau IIA is fully implicit: its stage equations are coupled, and a direct simplified-Newton iteration ordinarily operates on an sd-by-sd system for s stages and d state variables. Radau IIA therefore offers high order and stiff stability, but its coupled storage and linear-algebra costs are structurally less attractive for a small MCU than sequential SDIRK stages unless the system is very small or a specialized transformation is used. DIRK methods can also exhibit stiff order reduction because their stage order is at most two, and at most one when the Runge, Kutta matrix is nonsingular.

  • Rosenbrock methods replace nonlinear stage solves with one linear solve per stage.
  • A common Rosenbrock diagonal coefficient permits reuse of one matrix factorization across all stages.
  • SDIRK stages are sequential backward-Euler-type nonlinear solves, with reusable linear algebra under simplified Newton.
  • Radau IIA stages are coupled; straightforward simplified Newton uses an sd-by-sd system.
  • Functional iteration avoids Jacobian construction but is documented as suitable only for mildly stiff problems.
  • A fixed iteration count gives deterministic work but is not automatically equivalent to a converged implicit RK step.
  • Published generalized RK constructions can preserve order and stability with specifically designed finite Newton iterations; arbitrary early termination has no such general guarantee.
  • Fixed-point iteration convergence can impose a stricter step-size restriction than truncation-error control.
