About the project ↗

Explicit Runge-Kutta methods build each stage from stages already computed, so a step is a fixed run of multiply-adds. For each order, stage count and cost, the grid keeps the verified tableau with the lowest held-out error, and that error, measured in Q15 at a fixed cycle budget, is the number each elite reports.

How to read this

The archive is a MAP-Elites structure: one grid per algebraic order 1 to 4, whose cells are keyed by (stage count, cycle bucket). A cell holds at most one record, its elite: the verified tableau with the lowest held-out error seen so far for that shape and cost; ties keep the earlier record. An empty cell means no verified tableau has landed there yet.

Stage rows span 2 to 6 by default, plus a row for any other stage count that holds an elite (order 1's single-stage cell appears as s=1). The cycle buckets are log2-spaced bins of the m0plus_fast cycles per step: bucket 0 means fewer than 16 cycles, bucket 1 is 16 to 31, bucket 2 is 32 to 63, doubling each column, and bucket 7 collects everything at 1024 cycles or more.

Every elite in one table (18 rows)

One row per occupied cell, every order together so cells can be compared across orders. The hash links to the full record. Beyond the search problems

On 4 of 5 practical problems that no search saw, the best discovered tableau ends with lower Q15 error than the best classical anchor at the same cycle budget. The validation tab has every method on every problem, the stiff ones included.

Measured wall clock agrees with the cycle model: in the benchmark head-to-head the champion tableau (11e898cb) runs in 20.47 us per Q15 step against 31.993 us for rk4 (medians across 7 problems, geometric-mean per-step speedup 1.452x). Details are in the measured speed section.

Measured against real counterparts, at matched accuracy

Our solvers reached 65 of their 96 targets; a target is one solver on one problem at one accuracy level. SciPy exposes no fixed-step integrator, so there is no library counterpart to run at a matched step count. The closest library code is an explicit Runge-Kutta pair under a step controller, which is measured in the adaptive class. The float64 rk4 row is the arithmetic control for this class and it is ours, not a library. Where our runs carry a cycle count, a reached target costs a median of 858 analytic cycles; the table gives each row's cost grade.
